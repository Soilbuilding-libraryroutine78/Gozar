# Deploying Gozar behind Nginx (reverse proxy + subdomain)

This directory holds a production-ready reverse-proxy configuration that puts a
single, modestly hardened public entrypoint in front of a Gozar stack started with
`compose.prod.yml`. The application containers bind to **loopback only**
(`127.0.0.1:8000` backend, `127.0.0.1:8080` console), so Nginx — terminating TLS,
applying security headers, rate limiting, and request-size limits — is the only
thing exposed to the network.

```
client ──HTTPS──> Nginx (TLS, rate limit, headers) ──> 127.0.0.1:8000  (backend /api, /v1)
                                                   └──> 127.0.0.1:8080  (console SPA)
```

## Files

| File | Install location | Purpose |
| --- | --- | --- |
| `gozar.conf` | `/etc/nginx/sites-available/gozar.conf` (symlink into `sites-enabled/`) | **Public server**: HTTP→HTTPS redirect + TLS server block, rate limiting, hardening. |
| `gozar-local.conf` | `/etc/nginx/sites-available/gozar.conf` | **Local/dev** variant using a single `listen 80; 443 ssl` block with a self-signed cert. |
| `gozar-http.conf` | generated by `setup-domain.sh` | HTTP-only bootstrap server block for certbot's `--nginx` flow. |
| `gozar-ratelimit.conf` | `/etc/nginx/conf.d/gozar-ratelimit.conf` | `limit_req`/`limit_conn` zones (HTTP context; used by `gozar.conf`). |
| `gozar-proxy.conf` | `/etc/nginx/snippets/gozar-proxy.conf` | Shared `proxy_set_header` block included by each location. |
| `setup-domain.sh` | run manually as root | Optional helper that installs `gozar-http.conf` for `GOZAR_DOMAIN` and requests a Let's Encrypt certificate. |

Use **either** `gozar.conf` (public, Let's Encrypt) **or** `gozar-local.conf` (local,
self-signed) — not both for the same hostname.

## Option A - local / self-signed

Uses one server block on 80+443 with a self-signed cert in `/etc/nginx/ssl/`.
Use when the subdomain resolves to this
box (via local DNS or `/etc/hosts`).

```bash
# 1) Self-signed cert (change the hostname to your subdomain).
sudo openssl req -x509 -nodes -newkey rsa:2048 -days 825 \
  -keyout /etc/nginx/ssl/gozar.local.test.key \
  -out    /etc/nginx/ssl/gozar.local.test.crt -subj "/CN=gozar.local.test"

# 2) Edit deploy/nginx/gozar-local.conf -> set server_name + the two ssl_* paths.
sudo cp deploy/nginx/gozar-local.conf /etc/nginx/sites-available/gozar.conf
sudo ln -s /etc/nginx/sites-available/gozar.conf /etc/nginx/sites-enabled/gozar.conf

# 3) If it only resolves locally, map it to this host:
echo "127.0.0.1 gozar.local.test" | sudo tee -a /etc/hosts

# 4) Validate and reload (nginx -t guards the reload, so other sites stay up).
sudo nginx -t && sudo systemctl reload nginx
```

## Option B - public server (Let's Encrypt + rate limiting)

## Prerequisites

1. **DNS**: point your subdomain (e.g. `gozar.example.com`) at the server's public IP (an `A`/`AAAA` record).
2. **The stack is running** and healthy:
   ```bash
   cp .env.example .env   # then fill in real secrets (see the root README)
   docker compose -f compose.prod.yml up -d --build
   curl -s http://127.0.0.1:8000/health    # -> {"status":"ok",...}
   ```
3. **A TLS certificate** for the subdomain (Let's Encrypt / certbot below).

## Install

Replace `gozar.example.com` with your subdomain in `gozar.conf` (both `server_name`
lines and the three `ssl_*`/cert paths) first.

```bash
# 1) Zones (HTTP context) and the shared proxy snippet.
sudo cp deploy/nginx/gozar-ratelimit.conf /etc/nginx/conf.d/gozar-ratelimit.conf
sudo mkdir -p /etc/nginx/snippets
sudo cp deploy/nginx/gozar-proxy.conf /etc/nginx/snippets/gozar-proxy.conf

# 2) The server block.
sudo cp deploy/nginx/gozar.conf /etc/nginx/sites-available/gozar.conf
sudo ln -s /etc/nginx/sites-available/gozar.conf /etc/nginx/sites-enabled/gozar.conf

# 3) Obtain a certificate (HTTP-01). The :80 server block already serves the
#    ACME challenge from /var/www/certbot.
sudo mkdir -p /var/www/certbot
sudo certbot certonly --webroot -w /var/www/certbot -d gozar.example.com
#    (or: sudo certbot --nginx -d gozar.example.com to let certbot edit TLS for you)

# 4) Validate and reload — `nginx -t` never reloads a broken config, so your other
#    sites stay up if anything is wrong.
sudo nginx -t && sudo systemctl reload nginx
```

> Adding a new `server_name` does not affect your existing virtual hosts: Nginx
> routes by host, and `nginx -t` guards the reload. The config only proxies to
> loopback ports, so it cannot reach anything else on the box.

## Verify

```bash
curl -s https://gozar.example.com/health                  # backend liveness
curl -s https://gozar.example.com/api/auth/bootstrap       # {"bootstrap_required": true|false}
# OpenAI-compatible call (after you create a Client_Token in the console):
curl https://gozar.example.com/v1/models -H "Authorization: Bearer gz-..."
```

Open `https://gozar.example.com/` in a browser to reach the console and complete the
first-run admin bootstrap.

## Security knobs (tune to taste)

- **Rate limits** live in `gozar-ratelimit.conf`: `gozar_auth` (10 r/m, strict — blunts
  credential stuffing), `gozar_admin` (30 r/m), `gozar_api` (120 r/m for `/v1`). Raise
  or lower per your traffic.
- **Request size**: `client_max_body_size 25m` in `gozar.conf` caps prompt bodies.
- **Make the admin console private** (optional): there is a commented `allow/deny`
  block in `gozar.conf` under `location /api/`. Uncomment it and set your office/VPN
  ranges to keep `/api` private while leaving `/v1` open to applications. (Per the
  brief this is left open by default — it is a one-line opt-in.)
- **Behind Cloudflare / another proxy?** Add `set_real_ip_from <proxy-cidr>;` and
  `real_ip_header X-Forwarded-For;` so the rate-limit keys use the true client IP.
- **HSTS** is enabled (`Strict-Transport-Security`); only keep it if you always serve
  this subdomain over HTTPS.

## Notes

- `/v1` is configured for **SSE streaming** (`proxy_buffering off`, long read timeout)
  so streamed chat completions flow chunk-by-chunk.
- The backend self-migrates on container start (`alembic upgrade head` via the image
  entrypoint), so there is no separate migration step after `compose up`.
